# 岛仔 × 喜鹊助手：显示层联动可行性（修正版）

> 对象：[[Ideas/岛仔 Daozai Windows桌面信息岛_2026-11-12|岛仔 Daozai]] × [[Projects/火柴复现工程/CONTEXT|喜鹊助手]]
> 前置更正：上一版把联动对象当成 JY-ERP，已作废。本文只谈**屏上形态与共存**。
> 一句话结论：**你想到的不是「联动」，是两个东西在抢同一块屏。真正该做的三件事里，两件不需要写任何互联代码，第三件（改岛仔）我不建议做。**

---

## 1. 先把两个东西搞清（决定天花板）

| | 岛仔 Daozai | 喜鹊助手 |
|---|---|---|
| 技术 | **Rust + eframe/egui 原生窗口**（非 Web） | Tauri 2 + Rust + **WebView 前端** |
| 形态 | 无边框透明窗 + 托盘；**顶部停靠**（收起=胶囊，展开=419×140 面板）+ **左右侧边停靠**（收起=36pt 竖胶囊） | **居中悬浮框**（双击 Ctrl 唤出）+ 独立 AI 面板 |
| 生命周期 | **常驻**，一直在屏上 | **按需**，不用时不存在 |
| 输入方式 | 鼠标友好（hover / 点击 / 展开） | 全键盘闭环（不碰鼠标） |
| 数据来源 | SMTC 媒体、Windows 通知库 `wpndatabase.db`、电量、日历、AI 额度、邮件 | Everything 本地搜索、DeepSeek、计算器/翻译 |
| 状态 | **已发布、每天多次提交**（689★，MIT） | **零代码，PLAN 待批准** |

### 一个决定性事实

我把岛仔仓库拉下来核过：**它没有任何插件机制、没有本地 HTTP 服务、没有命名管道、没有命令行参数入口**。就是一个自包含的原生窗口程序（`src/main.rs` 是 Win32 外壳，界面全在 `daozai::app::App`）。

所以你脑里那种「两个程序互相喂数据」的联动，**目前根本没有接口**。想连，只有三条路，下面第 3 节讲。

---

## 2. 先说不同意的：你看到的是形态，真正发生的是抢位

你被岛仔吸引的是它的**两态语言**：收起时一条小胶囊安静地挂着，展开时才把信息铺开。这确实是喜鹊悬浮框目前缺的东西——喜鹊现在只有「出现」和「消失」两态，没有「最小占位」态。

但把这两玩意放到一起，重瞈的不只是像素：

| 重瞈点 | 具体表现 |
|---|---|
| **位置** | 两个都想占屏幕顶部。岛仔已经住了，喜鹊想学它就必然撞 |
| **信息** | 岛仔已有：AI 额度、待办、专注计时、通知、音乐。喜鹊的 Panel 迟早也想做这些 |
| **入口身份** | 两个都想当「桌面唯一入口」。一个靠双击 Ctrl，一个靠鼠标点 |

**所以真正的问题不是「怎么连」，是「怎么分工」。** 下面第 3 节的三条路，前两条本质都是分工而不是互联。

---

## 3. 三条路（按我推荐的顺序）

### 路 A · 只借语言，不做互联（推荐，真正该做的）

喜鹊 HUD 学岛仔的**两态动效与视觉语言**，但**不学它的常驻**。

- 收起态：不存在（喜鹊本来就按需唤出）
- 唤起态：从顶部一条细横条**展开**成输入框（150–200ms、带回弹），而不是现在的「直接出现一个矩形」
- 结果区：卡片从岛体向下展开，而不是跳列表
- **入口**：双击 Ctrl（不变）
- **数据流**：无。两边零交互
- **改动点**：仅喜鹊前端 CSS/动效 + HUD 两阶段渲染；**Rust 侧零改动**
- **为什么推荐**：它让你得到了你真正想要的那个「感觉」，但没给你背上一个常驻进程、没抢岛仔的地盘、没破坏喜鹊的全键盘闭环

### 路 B · 屏幕分区契约（零代码，今天就生效）

不联动，但约定互不侵犯：

- 岛仔设置里选**顶部停靠**（或侧边），喜鹊悬浮框保持**屏幕中心偏上**呼出
- 岛仔的展开面板高度约 140pt，喜鹊 HUD 顶部起始位置下移一个安全距（例如 8–12pt），避免唤起时遮住岛体
- **入口**：无需入口，各用各的
- **改动点**：岛仔里改一个设置项 + 喜鹊 HUD 定位常量里加一个 ``avoidTop`` 值
- **代价**：几乎没有。**收益是避免以后你自己両个都不想要**

### 路 C · 真·进程联动（改岛仔源码；我不建议）

唯一技术上说得通的方式：**约定文件 + 单向只读**。

- **入口**：喜鹊写完结果后，把状态写到 `%LOCALAPPDATA%\Xique\island.json`；岛仔（**需 fork 改源码**）读它，在岛上多一个「喜鹊」槽位
- **数据流**：喜鹊（写）→ 状态文件 → 岛仔（读、渲染）——**单向、永不回写**
- **操作路径**：Ctrl Ctrl → 输「华邦」→ 喜鹊出结果的同时，岛上那一条变成「3 条本地结果」→ 点岛上那条重新打开喜鹊
- **为什么我不建议**：
  1. **你得维护一个 fork**。岛仔一天多次提交，你的 fork 一顿就怒。除非你先把它做成 PR 合进上游，但那意味着你要说服作者接受一个「给别的软件留槽」的设计
  2. **收益极小**：喜鹊本来就是「叫出来→用完就消失」。让岛仔帮你显示它，等于把瞬时结果变成常驻噪音
  3. **它把两个没稳的东西绑死了**：喜鹊零代码，岛仔天天变
- **如果一定要做**：先写个 Issue 问作者要不要加「外部状态槽」，而不是先写代码

## 4. 成本与兼容性

（照旧不给日历周期，只给改动面）

| 路径 | 喜鹊改动 | 岛仔改动 | 前置 | 风险 |
|---|---|---|---|---|
| A 视觉语言 | 前端动效 + HUD 两阶段渲染 | 无 | 无 | 低（需实测展开时首字输入不丢焦点） |
| B 分区契约 | 1 个定位常量 | 1 个设置项（默认已是顶部） | 无 | 无 |
| C 文件联动 | 1 个写状态模块 | **fork + 新槽位渲染** | 上游接受/自己维护 | 高 |

### 兼容性注意（针对路 A）

1. **焦点**。Tauri HUD 在「先展开再聚焦」的两阶段里很容易丢输入焦点（窗口动画期间 IME 也会捣乱）。这是路 A 唯一真正的技术坑，必须在 M1 阶段就拿中文输入法测。
2. **透明与合成**。岛仔用 egui + 透明窗（还有毛玻璃/D3D12 回退那堆事）。喜鹊是 WebView，两者视觉细节不可能完全一致——**别追求像素级一样，只借节奏和比例**。
3. **DPI/多屏**。岛仔已有 `display_layout.rs` / `avoidance.rs` 在管多屏与避让；喜鹊 PLAN 里 M0 就要做多屏定位。两边都自己管，不需要互相知道。

## 5. 优先级

| 优先级 | 做什么 | 何时 |
|---|---|---|
| 1 | **路 B 分区契约**（写在喜鹊 PLAN 的 HUD 定位里：顶部留 140pt 安全区） | 开工时一并落地，零成本 |
| 2 | **路 A 视觉语言**（仅限展开动效与胶囊讨比例） | 喜鹊 M1（调度器与纯本地能力）做完后调形 |
| 3 | 路 A 的「收起态常驻胶囊」 | **不做**。喜鹊是瞬时工具，常驻就变成第二个岛仔 |
| — | 路 C fork 岛仔 | 不做，除非先拿到上游 PR 口子 |

## 6. 定位与 UX 一致性校验

| 判定项 | 结论 |
|---|---|
| 喜鹊「一个输入框」 | 路 A 只是换了个入场方式，没有新增窗口/入口 | ✅ |
| 喜鹊全键盘闭环 | 路 A 不引入鼠标交互；两阶段动画不得阻断输入 | ✅（需实测） |
| 喜鹊「按需唤出」 | 路 A 不做得常驻；路 C 会把瞬时结果变懒留 | ⚠️ 路 C 违反，路 A 不违反 |
| 岛仔「低打扰常驻」 | 路 A/B 都不碰岛仔 | ✅ |
| 岛仔「鼠标友好」定位 | 路 C 要让岛服务于键盘工具，与它自己的定位相揝 | ⚠️ 路 C 有张力 |
| 双工具信息不重复 | 待拍板：**喜鹊不做 AI 额度/待办/音乐，岛仔不做搜索** | 需你点头 |

**两句话需要你拍板**：

1. **喜鹊到底要不要有「收起胶囊」这个态？** 我建议不要。你一收起，它就从「叫出来就用」变成「一直在那里」，而那正是岛仔的位置。
2. **两者功能重叠区划给谁？** 我的建议：**岛仔管「 passively 看」，喜鹊管「 actively 找」**。放弃了这条，两边都会长成四不像。

## 7. 下一步（三件，都不必写代码）

1. 在喜鹊 PLAN 的 M0 里加一条常量：HUD 顶部避让 140pt（对应岛仔展开面板）
2. 写进喜鹊 CONTEXT 的术语表：`两态展开`（胶囊→输入框），标注「借自岛仔的形态语言，不引入常驻」
3. 如果你还是想要真联动，先去岛仔仓库开 Issue 问作者是否愿意加「外部状态槽」——**一个 Issue 的成本，比一个 fork 小两个数量级**
